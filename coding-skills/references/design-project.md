# 设计项目

根据任务范围设计目标结构、文件职责和接口。

## 设计结构

- 确定目标目录树、目录职责、文件位置和文件职责。
- 项目根目录放 README 等项目文件；应用代码集中在 `app/` 等源码目录。
- 源码目录顶层放启动或组织文件（如 `main.py`、`app.py`）、配置文件，以及语言或框架必需的文件。
- 组织文件专门负责创建实例、注册组件、注入依赖和连接调用关系；业务逻辑归入对应职责文件。
- 其余代码按定位或功能归入源码目录下的一级职责目录，目录边界由职责决定。
- 功能文件直接放在职责目录中；确有独立子系统或框架约束时再增加目录层级。
- 明确文件间的单向依赖，由组织文件连接模块。

```text
project/
├── README.md
└── app/
    ├── main.py
    ├── config.py
    ├── routers/
    │   ├── items.py
    │   └── users.py
    ├── shared/
    │   └── get_current_user.py
    ├── exceptions/
    │   └── not_found_exception.py
    └── middleware/
        └── add_request_id_header.py
```

## 设计文件

- 确定每个文件的主要类型、函数、数据和状态，以及对外接口。
- 资源文件集中放置该资源的入口、专属模型、局部状态和辅助逻辑。
- 认证、配置、加密、异常处理和中间件等横切能力按功能独立。
- 简单且只服务一个调用方的逻辑留在使用位置；独立职责、公共契约或共享状态单独成模块。
- 文件名直接表达职责并遵循语言规范。

例如，条目模型、分页规则和内存状态只服务条目接口时放在 `items.py`；认证属于横切安全能力，即使暂时只有一个调用方，也放在独立文件中。

## 规划变化

结构变化时，列明文件的新增、移动、拆分、合并和删除关系，以及消费者迁移顺序、兼容要求和旧结构清理条件。
