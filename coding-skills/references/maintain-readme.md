# 维护 README

将 `README.md` 作为项目结构地图，帮助读者快速定位代码，并随项目演进维护。

## 建立 README

- 空白项目：主要编码前建立 README，记录目标、运行入口和初始设计；完成后同步实际结构。
- 现有项目：先读取 README 并核对相关事实；缺少 README 时依据项目事实建立。

## 组织内容

新 README 按以下顺序组织；已有 README 沿用清晰的结构。

1. **项目概览**：项目目标、核心能力和运行方式。
2. **项目结构**：完整目录树，以及每个目录和源码文件的职责。
3. **模块与接口**：每个文件的主要模块、类型、关键函数、公共接口和调用关系。
4. **依赖与数据**：模块依赖方向、外部依赖、配置入口、数据和状态归属。
5. **开发验证**：安装、运行、测试、静态检查和构建命令。

目录树表达层级，代码块展示可执行命令；每项事实只在一处完整说明。

## 持续维护

- 开始时用 README 定位代码，并核实任务涉及的事实。
- 计划时找出受影响的章节；完成后依据最终实现更新这些内容，清理失效信息。
- 交付前核对路径、命令、接口、依赖和结构。

README 记录稳定的结构事实，使用代码中的实际名称；私有实现由代码表达。
